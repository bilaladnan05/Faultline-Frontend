# Frontend roadmap

The frontend follows the backend roadmap in `Faultline-Backend/.planning/ROADMAP.md`. See [BACKEND-PARITY.md](./BACKEND-PARITY.md) for the audited gaps and execution contract.

- [ ] Phase 1 parity: expose cluster/source health, bounded intake diagnostics, and safe credential lifecycle outcomes.
- [ ] Phase 2 parity: make incident/evidence identity and provider degradation explicit without blocking the incident core.
- [ ] Phase 3 parity: ship the diagnosis workspace for revisions, evidence packs, blast radius, hypotheses, citations, stale state, and read-only tests.
- [ ] Phase 4 preparation: wait for backend contracts, then add governed response/evaluation views with no production execution controls.
- [ ] Phase 5 preparation: wait for backend contracts, then add curated memory and release-candidate validation views.
